## Quick Reference

- **Design Loop:** Empathize → Define → Ideate → Prototype → Test → Implement
- **Sprint Days:** Monday (Research) → Tuesday (Ideation) → Wednesday (Critique) → Thursday (Prototype) → Friday (Test)
- **Research Methods:** User interviews, contextual inquiry, surveys, diary studies
- **Testing:** Usability testing, A/B testing, card sorting

## Procedure

1. **Empathize** — Conduct user research: interviews, surveys, observations, analytics review
2. **Define** — Synthesize findings into problem statements and success metrics
3. **Ideate** — Brainstorming sessions, Crazy 8s, How Might We questions
4. **Prototype** — Build low-fi paper sketches through high-fi clickable prototypes
5. **Test** — Usability sessions, A/B testing, iterate based on findings
6. **Implement** — Design specs, developer collaboration, QA, post-launch monitoring

## Pitfalls

- **Skipping empathy research** — Without user insights, solutions may miss the mark
- **Analysis paralysis in ideation** — Set time limits to generate volume over perfection
- **Over-investing in high-fi early** — Test concepts with low-fi first
- **Ignoring accessibility** — Design systems should be WCAG compliant from the start
- **Unclear handoff** — Design specs and tokens must be explicit for developers

## Verification

- Research artifacts created: personas, empathy maps, journey maps
- Problem statements documented with success metrics
- Prototypes tested with 3-5 users minimum
- Design specs include tokens, dimensions, states
- Post-launch: metrics tracked, feedback collected monthly
